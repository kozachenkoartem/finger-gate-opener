# Регистрация отпечатков и проверка открывания

## Реализовано

- HTTPS-интерфейс: список отпечатков, регистрация, отмена, имя, роль и удаление.
- Новая запись всегда активный `User`; роль `Master` назначает администратор
  отдельно. Обе роли могут открывать, активных Master не больше двух.
- Регистрация: четыре сканирования с полным снятием пальца между ними,
  один общий deadline 120 секунд, проверка дубликата и свободного слота.
- Локальное распознавание работает независимо от Wi-Fi и HTTPS.
- GPIO8 — временный индикатор выхода реле: active-low импульс 1000 мс.
  Прежнее heartbeat-мигание удалено. GPIO10 не настраивается.
- После принятого импульса — cooldown 10000 мс, без продления повторными
  совпадениями. Удержание пальца не вызывает новых открываний; снятие и касание
  подавляют дребезг длительностью менее 30 мс.
- Три отдельных совпадения одного Master в фиксированном окне 10 секунд после
  отпускания третьего касания запускают одну локальную регистрацию нового User.
  Совпадения во время cooldown также считаются для жеста. Другой палец сбрасывает
  последовательность. Локальное имя по умолчанию — `Палец №N`.

Единственный владелец UART1, registry и UserStore — fingerprint task. Web-команды
передаются через очередь из восьми элементов; за проход выполняется не более
одной команды. API возвращает 202 с `command_id`, результат находится в восьми
последних квитанциях снимка. Принятие в очередь не означает успешное выполнение.
Запрос отмены содержит ID конкретной регистрации и не отменяет более новую.

Обработка GPIO8 вынесена в аппаратный GPTimer: alarm и GPIO control находятся
в IRAM, cache-safe ISR выключает выход при записи NVS и независимо от ожидания
UART. Таймер ставится до включения GPIO8 в критической секции. Это стендовый LED,
а не подключённое к калитке физическое реле.

## HTTP API

Используются существующие HTTPS session и CSRF; начальный пароль должен быть
заменён. POST принимает плоский JSON со строковыми полями, максимум 1024 байта.

| Путь | Метод и поля |
| --- | --- |
| `/api/fingerprints` | GET: пользователи, карантин, регистрация, последнее решение и квитанции |
| `/api/enrollment/start` | POST: `name` (необязательно, до 64 байт) |
| `/api/enrollment/cancel` | POST: `operation_id` |
| `/api/users/rename` | POST: `slot`, `name` |
| `/api/users/role` | POST: `slot`, `role` (`User` или `Master`) |
| `/api/users/delete` | POST: `slot` |

Slots находятся в диапазоне 0–99. Неизвестные, неактивные и карантинные записи
не дают доступ. Web endpoint непосредственного открытия отсутствует.

## Сохранность и восстановление

До изменения сенсора сохраняется намерение. Мутирующие UART-команды не
повторяются автоматически. Неоднозначный store/delete проверяется чтением
индекса и, для store, поиском текущего шаблона. При невозможности подтверждения
слот исключается из доступа и распределения. При загрузке сверяются сенсор и
метаданные; автоматической очистки базы датчика нет.

Изменения имени/роли не меняют сенсорный шаблон. Перед разрушительным откатом
неудачной фиксации подтверждается отдельный NVS-маркер карантина. Если хранилище
не позволяет подтвердить даже этот маркер, шаблон сохраняется, а результат —
`commit_indeterminate`/`update_indeterminate`: это не подтверждение успешного
отката. После reboot при отсутствии сохранившегося запрета может восстановиться
целостная committed-запись. Такой результат требует проверки списка и карантина
администратором. При полном отказе записи NVS гарантировать сохранение нового
запрета после reboot невозможно.

## Проверки перед аппаратной приёмкой

- Host CTest: 9/9 целей; controller — 21 группа сценариев, включая многократные
  отказы хранения, потерю подтверждения записи/удаления, reboot, deadline,
  held-finger, Master limit/gesture и cooldown от фактического timestamp выхода.
- Проверена синтаксическая корректность встроенного JavaScript.
- ESP-IDF build и размещение ISR/GPIO/GPTimer control в IRAM проверяются перед
  прошивкой. Визуальная индикация, реальная длительность GPIO8 и физические
  сканирования требуют проверки на плате.

## Приёмка пользователем

1. Открыть HTTPS-панель и войти своим сохранённым паролем. Должен появиться
   раздел **Fingerprints**. При старой странице выполнить полное обновление.
2. Убедиться: GPIO8 не мигает в ожидании и не даёт импульса при включении.
   Кольцо R558S в ожидании синее.
3. Ввести имя и нажать **Add fingerprint**. Кольцо жёлтое. По подсказкам
   приложить один и тот же палец четыре раза, полностью снимая его между
   сканированиями. Уложиться в 120 секунд.
4. Дождаться результата `enrolled`, трёх зелёных вспышек и возврата к синему.
   В списке появляется `User`. Полностью убрать палец после регистрации.
5. Приложить зарегистрированный палец: GPIO8 должен загореться примерно на одну
   секунду и погаснуть. В **Refresh fingerprints / last access** — `granted`.
6. Удерживать палец: повторного импульса не должно быть. Убрать и повторно
   приложить раньше десяти секунд: GPIO8 не включается, решение `cooldown`.
   После cooldown новое отдельное касание снова разрешает импульс.
7. Приложить незарегистрированный палец: три красные вспышки, GPIO8 не включается.
8. Нажать **Set Master** у нужной записи. Роль должна обновиться сразу. Открывание
   этим пальцем по-прежнему работает. Третьего Master назначить нельзя.
9. Перезапитать плату: пароль, имя/роль и отпечаток сохраняются. GPIO8 при старте
   не включается; распознавание работает снова. Проверить и при отключённом Wi-Fi.
10. Для Master-жеста сделать три отдельных касания того же Master за десять
    секунд. После снятия пальца с третьего касания должен включиться жёлтый
    режим регистрации. Зарегистрировать другой палец; он должен стать User.

Дополнительно проверить отмену, duplicate, timeout, переименование и явное
удаление тестового отпечатка через кнопку с подтверждением. Физические тесты
регистрации и удаления автоматически не запускаются.
