# HTTPS-администрирование

Реализована основа Tasks 6–7 общего плана: вход, обязательная смена начального
пароля, сессии, CSRF, статус сети и защищённая первоначальная настройка Wi-Fi.
Управление отпечатками и индикатор открывания описаны в
[`fingerprint-access.md`](fingerprint-access.md). Настройка длительности реле,
recovery AP и постоянный журнал аудита остаются следующим этапам общего плана.

## Доступ

- В локальной сети: `https://finger-gate-XXXX.local/` либо `https://<STA-IP>/`.
- В первоначальном AP: `https://192.168.4.1/`. HTTP на этом адресе содержит
  только ссылку на HTTPS, без API изменения настроек.
- Первые credentials: `admin` / `admin`. До замены пароля недоступны даже
  защищённый статус и настройка Wi-Fi. Новый пароль: 12–128 байт UTF-8.
- После замены пароля все сессии завершаются; требуется повторный вход.
- Сертификат самоподписанный: при первом открытии браузер потребует явно
  подтвердить доверие сертификату устройства. Для IP и `.local` это отдельные
  адреса браузера. Сертификат содержит DNS SAN `finger-gate-XXXX.local`.

Для каждой платы генерируется собственная пара P-256 ключ/сертификат, сохраняемая
одной NVS-записью. Исходники и бинарник не содержат общего приватного ключа.
При перезагрузке сертификат сохраняется; испорченная запись не заменяется молча.
Заявленный срок сертификата: 2024–2049. Закрытый ключ находится в обычном NVS;
защита flash от физического чтения этим этапом не добавляется.

## Контракт API

Все перечисленные API обслуживаются только TLS-сервером на порту 443.

| Метод/путь | Назначение |
| --- | --- |
| `POST /api/login` | JSON `username`, `password`; устанавливает cookie |
| `GET /api/session` | CSRF-токен и `password_change_required` |
| `POST /api/password` | JSON `new_password`; завершает все сессии |
| `POST /api/logout` | JSON `{}`; завершает текущую сессию |
| `GET /api/status` | Статус устройства и адреса без секретов |
| `POST /api/wifi` | JSON `ssid`, `password`; только в первоначальном AP |
| `POST /api/acknowledge` | JSON `{}`; закрывает AP после отправки ответа |

Кроме login все API требуют cookie; POST также требует `X-CSRF-Token`.
Во время обязательной замены пароля разрешены только session/password/logout.
Cookie: `__Host-fg_session`, `Secure`, `HttpOnly`, `SameSite=Strict`, `Path=/`.
JSON ограничен 1024 байтами; неизвестные/дублированные поля, вложенные объекты,
массивы, неполный JSON и NUL отвергаются. Пароль проверяется через
PBKDF2-HMAC-SHA256, 60000 итераций и индивидуальную 16-байтовую соль.
Сравнение проверочных хешей и токенов — constant-time.

До четырёх сессий: 15 минут без запросов либо 8 часов абсолютного времени.
Пять неверных входов блокируют вход на 60 секунд. Сессии и счётчик блокировки
хранятся в RAM, пароль — в NVS. Результаты входа/смены пароля/настройки сети
пишутся в serial log без credentials; постоянный аудит относится к Task 8.

Wi-Fi credentials сохраняются только после получения STA IP. AP закрывается
после подтверждения либо через пять минут после успешного подключения.
Обычный разрыв STA вызывает повторное подключение, не открывая AP.
mDNS объявляет только действующий `_https._tcp:443`.

## Проверено на устройстве 2026-11-03

Прошивка `122a1a9`, ESP32-C3, `/dev/ttyACM197`; NVS и partition table layout
сохранены. Сборка использует `-Os`, образ 0xe9580 байт помещается в app-раздел
0x100000. Host CTest: 8/8.

На реальной плате подтверждены:

- загрузка сохранённого Wi-Fi и STA IP `192.168.1.193`;
- HTTPS `/` по IP и `finger-gate-a31d.local`: HTTP 200;
- `/api/status` без cookie: 401;
- login `admin/admin`: 200 и все обязательные cookie-флаги;
- session сообщает обязательную замену пароля; status и Wi-Fi до замены: 403;
- замена пароля без CSRF: 403;
- logout с CSRF: 200, старая сессия затем даёт 401;
- 1024 вложенные открывающие скобки на login: 400, сервер продолжает работать;
- после дополнительной перезагрузки повторены эти проверки; SHA256 сертификата
  не изменился. Пароль администратора и Wi-Fi credentials проверками не менялись.

Визуальная индикация и полный AP→STA сценарий этой версии ещё требуют ручной
приёмки. Сохранённую конфигурацию ради этого автоматически не стирали.

Дополнительно подтверждено пользователем: пароль администратора заменён через
веб-интерфейс; после полного отключения и повторного включения питания вход
с новым паролем успешен. Отказ старого пароля, отсутствие AP и индикация этим
сообщением отдельно не подтверждены.

## Что проверить вручную сейчас

1. Открыть `https://192.168.1.193/` и подтвердить сертификат устройства.
2. Войти `admin/admin`: интерфейс должен предложить обязательную замену пароля.
3. Задать свой пароль длиной от 12 байт; повторно войти с ним.
4. Проверить страницу статуса: STA IP, hostname, AP off. Кольцо — постоянно синее.
5. Выйти: доступ к статусу без входа закрыт.
6. Перезагрузить плату. AP не появляется; новый пароль сохраняется; старый
   `admin` больше не подходит. HTTPS доступен по IP и `.local`.

Полную AP-проверку проводить отдельно при намеренном сбросе только Wi-Fi
конфигурации: вход и замена пароля → неверная сеть/три красные/возврат к AP →
верная сеть/жёлтый/три зелёные/постоянный синий → статус с IP → подтверждение →
AP закрыт, HTTPS STA остаётся доступен. Отдельно проверить пятиминутный timeout.

## Host-тесты

Нужны CMake, C/C++ compiler, OpenSSL development headers и исходники ESP-IDF
(используется тот же cJSON, что и в прошивке):

```sh
. ~/esp/esp-idf-v5.5.3/export.sh
cmake -S firmware/tests -B /tmp/finger-gate-tests
cmake --build /tmp/finger-gate-tests
ctest --test-dir /tmp/finger-gate-tests --output-on-failure
```
