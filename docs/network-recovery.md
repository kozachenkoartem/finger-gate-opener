# Recovery AP и смена Wi-Fi

## Назначение

Из HTTPS-панели администратор может временно открыть `FingerGate-XXXX`,
подключиться к нему и сменить домашнюю сеть платы без USB и сброса NVS.
Пароль администратора и зарегистрированные отпечатки при этом не меняются.

Есть три независимых секрета: пароль администратора, пароль подключения платы
к выбранному Wi-Fi и пароль её собственной точки доступа FingerGate.
Изменение одного не заменяет остальные.

## Правила работы

- **Open recovery AP (5 minutes)** открывает WPA2 AP по адресу `192.168.4.1`.
  Повторное открытие активного AP не продлевает окно.
- Пароль AP по умолчанию — `fingergate`. В **Save AP password** можно задать
  индивидуальный пароль: 8–63 печатных ASCII-символа. Он сохраняется в NVS и не
  возвращается через API. Изменение разрешено только при выключенном AP.
- Новый пароль AP применяется до его объявления. Если пароль изменён, первое
  последующее открытие recovery AP кратко перезапустит Wi-Fi радио и подключение
  STA. Локальное распознавание и GPIO8 продолжают работать в своей задаче.
- Новая сеть проверяется до 30 секунд. До получения подтверждённого STA IP и
  успешной фиксации настроек прежние credentials остаются принятыми.
- При неверном пароле, таймауте, потере событий или ошибке сохранения плата
  возвращается к прежней сети. В статусе остаётся `last_trial: failed`.
- Пятиминутный recovery AP закрывается и при неудачной попытке/восстановлении.
  Закрытие AP не отменяет безопасное восстановление STA. Ошибка закрытия видна
  как `ap_closing` и повторяется с секундной паузой.
- **Finish setup and close AP** закрывает AP после отправки ответа, не дожидаясь
  полного окна. Для этого должна работать STA, без незавершённой проверки сети.
- Первоначальный AP устройства без credentials не имеет recovery-таймаута до
  первой успешной настройки; после неё закрывается по подтверждению либо через
  пять минут. Обычный разрыв STA никогда сам не открывает AP.

ESP32 использует одно Wi-Fi радио: смена канала при подключении к другой сети
может кратко отключить AP-клиента. Следует повторно подключиться к FingerGate
и открыть `https://192.168.4.1/` для проверки результата. HTTP на AP содержит
только ссылку на HTTPS. На новом адресе браузер может снова запросить доверие
самоподписанному сертификату; пароль администратора остаётся прежним.

## API и исполнение

Все POST требуют HTTPS, действующую сессию после замены начального пароля,
`application/json` и `X-CSRF-Token`.

| Запрос | JSON |
| --- | --- |
| `POST /api/network/recovery` | `{}` |
| `POST /api/network/ap-password` | `{"password":"..."}` |
| `POST /api/wifi` | `{"ssid":"...","password":"..."}` |
| `POST /api/acknowledge` | `{}` |

202 с `command_id` означает резервирование команды, а не успех подключения.
Проверять результат следует через `GET /api/status`: `network_command`,
`last_trial`, `ssid`, `sta_ip`, `ap_active`, `ap_ssid`, `ap_remaining_ms`,
`ap_password_custom`. Пароли, rollback-данные и проверочные хеши не возвращаются.

Запрос резервируется до отправки ответа и активируется только после успешной
отправки. Владелец сетевого состояния повторно проверяет допустимость операции.
Wi-Fi callbacks только копируют события в ограниченную очередь. У каждой смены
сети есть граница отключения и новая ассоциация; старый IP и события прошлой
попытки не подтверждают новую сеть. Потеря очереди инвалидирует ожидаемый успех.

Сохранение Wi-Fi использует старое значение/его отсутствие в NVS rollback guard:
guard → candidate → удаление guard → успех. Незавершённый guard имеет приоритет
при загрузке и восстанавливается идемпотентно. Повреждённые или недоступные
данные не заменяются значениями по умолчанию. Как и для других операций NVS,
полный отказ хранения не позволяет гарантировать запись нового запрета; такой
сбой требует проверки фактически сохранившегося состояния.

## Проверка на двух сетях без выключения роутера

1. Войти в текущую HTTPS-панель, полностью обновив страницу.
2. При выключенном AP задать свой пароль AP и дождаться сообщения о сохранении.
3. Нажать **Open recovery AP (5 minutes)**. Подключить ноутбук/телефон к
   `FingerGate-XXXX` новым AP-паролем, открыть `https://192.168.4.1/`, войти своим
   существующим паролем администратора.
4. Для отрицательной проверки указать вторую сеть с заведомо неверным паролем.
   Ожидать отказ, три красные вспышки, возврат к AP-пульсу и восстановление
   прежней STA. Старые настройки не должны исчезнуть.
5. Пока AP активен, указать правильные credentials второй сети. Ожидать жёлтую
   индикацию, затем три зелёные вспышки и постоянный синий. В статусе должны быть
   вторая SSID, новый STA IP и `last_trial: success`.
6. Нажать **Finish setup and close AP**, перейти ноутбуком/телефоном во вторую
   сеть и открыть новый HTTPS IP или `finger-gate-XXXX.local`.
7. Перезапитать плату: она должна подключиться ко второй сети без AP. Пароль
   администратора, роли и открывание отпечатком должны сохраниться.
8. Через recovery AP аналогично вернуться в первоначальную сеть.

Отдельно: открыть recovery AP и ничего не менять — через пять минут AP исчезает,
STA и открывание отпечатком продолжают работать. Проверка отключением домашнего
роутера не требуется.

Host suite включает переходы lifecycle, ошибки/перезапуск транзакции NVS,
stale/same-SSID события, потерю очереди, приём HTTP-команд и отображение отказа в
JavaScript. Реальную смену на вторую сеть выполняет пользователь через интерфейс;
credentials в чате не нужны.
