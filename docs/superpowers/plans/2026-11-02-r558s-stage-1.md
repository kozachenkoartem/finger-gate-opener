# R558S Stage 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the diagnostic UART exchange with a validated R558S protocol driver and verify its enrollment workflow on the real sensor.

**Architecture:** A platform-independent packet builder and stream parser validate every R558S frame before an ESP-IDF UART adapter exposes command transactions. Only the future fingerprint task may own this adapter; Stage 1 keeps a USB-only diagnostic surface and introduces no Wi-Fi, HTTP, relay, or persistent fingerprint data.

**Tech Stack:** C++17, ESP-IDF 5.5.3 UART driver, FreeRTOS, host CMake/CTest.

**Spec:** The approved Finger Gate Opener plan v2 in the session review record.

## Global Constraints

- UART1: GPIO4 RX, GPIO5 TX, 57,600 baud, 8N1; GPIO3 is `TOUCH_OUT` with no internal pull.
- Treat a response as successful only after header, address, packet type, length, checksum, command status, and command payload validation.
- A command has one absolute deadline; malformed, late, or stale replies cannot confirm a new command.
- Never delete all templates or overwrite an occupied slot during hardware verification.
- Registration timeout is 120 seconds; enrollment image count and LED mode bytes are verified on the actual R558S before later stages depend on them.
- No flash write or board interaction while the board is disconnected.

## Review Focus

- Fragmented UART frames must produce one packet only after all bytes arrive; test in Task 1.
- Garbage before a valid header must not prevent resynchronization; test in Task 1.
- A checksum or length error must be rejected rather than treated as an ACK; test in Task 1.
- A negative confirmation frame must remain distinguishable from a timeout; test in Task 2.
- A timeout after write must not automatically repeat a mutating enrollment or storage command; test in Task 2.
